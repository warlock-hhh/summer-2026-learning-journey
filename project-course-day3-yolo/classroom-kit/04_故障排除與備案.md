# 故障排除與課堂備案

## 判斷問題在哪一層

```text
系統 → Python → 虛擬環境 → 套件 → 權重 → 圖片 → 推論 → 輸出
```

不要一出錯就重裝全部套件。先找到失敗層級。

## 1. `externally-managed-environment`

原因：在 Debian／Raspberry Pi OS 的系統 Python 直接使用 pip。

處理：

```bash
cd ~/opencv-yolo-project
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

不要使用 `--break-system-packages`。

## 2. `.venv` 建立失敗

```bash
sudo apt update
sudo apt install -y python3-full python3-venv
python3 -m venv .venv
```

## 3. VS Code 使用錯誤 Python

終端執行：

```bash
python -c "import sys; print(sys.executable)"
```

若不是 `.venv/bin/python`：`Ctrl+Shift+P` → `Python: Select Interpreter` → 選 `.venv/bin/python`。

## 4. `No module named ultralytics`

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
```

再檢查：

```bash
python -c "import ultralytics; print(ultralytics.__version__)"
```

## 5. 找不到 `yolo26n.pt`

確認：

```bash
ls -lh weights/yolo26n.pt
```

課堂使用本地權重，不依賴自動下載。

## 6. 找不到圖片或結果為空

```bash
ls -lh images
```

先使用教師已驗證的基準圖片，並把 threshold 設回 `0.25`。

## 7. 推論很慢

- 關閉瀏覽器與不必要程式。
- 一次只處理一張圖。
- 確認 Pi 有散熱，避免 thermal throttling。
- 教師若已驗證 NCNN，可改用預先匯出的 NCNN 模型。
- 不在課堂上臨時嘗試超頻。

## 8. `cv2` 或圖形介面錯誤

本專案不需要 `cv2.imshow()`；結果直接存入 `outputs/` 再用檔案管理員或 VS Code 開啟。這可減少 GUI backend 問題。

## 9. pip 安裝在課堂中失敗

依序使用備案：

1. 兩人一組共用已成功的 Pi。
2. 複製教師已準備的完整專案與相容環境方案。
3. 使用教師備援 Pi 投影，學生改做結果解讀與 threshold 紀錄。
4. 直接提供三組已輸出的預測結果，完成 class、box、confidence、誤檢與漏檢分析。

課程成果是理解與完成推論流程，不應讓全班耗在下載進度。

## 10. 緊急縮時版本

若設備問題耗掉 30 分鐘：

- 保留：訓練／推論、分類／偵測、class／box／confidence。
- 保留：完整執行、threshold 實驗、新圖片測試。
- 刪除：IoU 細節、NMS 延伸、自訂類別訓練流程。

## 11. 上課後要記錄

- 哪一關失敗最多？
- 安裝花了多久？
- 每張圖平均推論時間？
- 哪種圖片最容易漏檢？
- 學生能否說出 confidence 不是 accuracy？
- 下次應預裝或刪除什麼？
